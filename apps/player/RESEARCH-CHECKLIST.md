# Research and competition UI — checks before implementation

- Page10 is a local adapter for same-origin fixed-release APIs. No wallet,
  signing, prepare, broadcast, deployment, private-store or custom RPC access.
- Author and distinct cranker are explicit. Only cranker executes STEP; author
  executes COMMIT, upload, seal, BEGIN and FINAL with its fixed nonce window.
- Private create requires six direct Organ IDs and explicitly supplied BIO graph;
  use CSPRNG32-byte requestId, retain it for identical retries, reset on changes.
- Creation exposes only public manifest allowlist. No automatic graph upload;
  confirmed COMMIT and manufacture window precede public synthesis stages.
- Bind every returned ACTION operation, nonce, stage, immutable workflow, caps,
  resources and Artifact. FINAL requires actual complete73-round observation.
- Public competition read distinguishes Winner recognition from current K
  activation. Round cursor progress is native/read driven; never rank in browser.
- Round/Winner actions are explicit intent handoffs to the existing console.
  No background advancement or automatic transaction execution.
- Input/navigation/config changes invalidate old handoffs; abort and generation
  checks reject delayed responses. Render safe summaries using textContent.
- Focused browser fixtures remain HOST-only. They do not establish new legal
  frontier, native execution, deployed readiness or mining earnings.
