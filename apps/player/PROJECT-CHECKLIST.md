# A1 project creation and sale browser layer

Status: local implementation, focused event tests and root browser layout/gate QA complete. Enabled transaction handoffs remain fixture-tested, not live-wallet acceptance. This checklist was written before implementation. Scope is an explicit read-only CREATE_PROJECT draft, known-project reads, original CREATE request reconciliation, and input-only handoffs. This layer cannot establish creation from a draft-derived ID or execute a transaction. Server configuration remains fixed and disabled by default. No real wallet, RPC, secrets, or deployment is used.

- [x] Preserve the five existing views; add a sixth independent project creation and sale view.
- [x] Keep native/guided modules intact. Use their bounded same-origin transport, configuration gates, exact intent validation and input-only transaction handoff. Root separately extended the transport action allowlist.
- [x] Send only exact project-plan/read/status bodies; require canonical u64 decimals, 1–64 UTF-8 name bytes without controls, all four ordered classes, caps 1–1,000,000 and unit prices at most u64 max minus 100,000. No artificial cap × price limit belongs to CREATE.
- [x] Label classes AA/NUC/LIPID/SUGAR in direct standard units / portions, without pack opening or recovery.
- [x] Accept a current CREATE_PROJECT ACTION only with explicit plan-only/no-execution flags; show nonce as unreserved and preview identifiers as uncreated draft data.
- [x] Show actual project ID and four material mints only after server actual-record verification, query binding, four-class/mint agreement, and decimals=0 checks. Never upgrade a draft preview into creation proof.
- [x] Distinguish exact original CREATE execution from a matching actual project after cached result overwrite. Require explicit original nonce (no default zero), lookup-only flags and receipt/project/mint agreement for an exact confirmation. Permit matching actual records to fill purchase without claiming original-request success.

Make purchase handoff an explicit verified-project-ID input/navigation action only; no planning, wallet, simulation, signing or sending runs automatically.
