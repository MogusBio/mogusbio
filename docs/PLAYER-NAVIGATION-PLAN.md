# 玩家导航整理与实施规格

实施状态更新：七入口和三市场页面已在主站及本机测试页落地。当前保留15个叶路由（原12个加三个市场页），原业务表单不重建；精确范围与验收见[统一导航验收](PLAYER-NAVIGATION-ACCEPTANCE.md)。下文保留实施前的审核和约束；真实手机设备及正式市场仍未验收。

日期：2026-10-25。范围：导航、页面名称、分组和入口交接；保留原有业务模块、12个内部 `data-view`、字段ID、权限、nonce、实验规则与科学/经济参数。本文件最初由只读审核形成；实际实施状态与验收以顶部更新及独立验收记录为准。

## 1. 七个一级入口

| 一级名称 | 子级与既有控制器 | 玩家看到的用途 |
| --- | --- | --- |
| 协议数据 | `economy` | 四类发行与LAB经济规则；现有算例不得写成实时链上统计 |
| 实验室项目 | 浏览项目 `directory`；创建/管理发售 `project` | 找项目、购买项目首发原料、创建自己的四类原料发售 |
| 生物工坊 | 设计实验 `builder`；制造部件 `manufacture`；逐层合成 `synthesis` | 原料→部件→细胞→器官→生物，按工作阶段切换 |
| 生物能 | `mining` | 产出登记、实际收益、领取、退出和恢复入口 |
| 我的资产 | `wallet-discovery` | 原料、余材、当前成品/生物和旧收益分类读取 |
| 交易市场 | 原料 `MATERIAL`；成品 `PRODUCT`；生物 `BIO` 三个独立页面 | 玩家转卖资产；主站与测试页使用相同分类名称 |
| 首创研究 | `research` | 私有提交、实验推进、轮次及首创结果 |

底部保留“玩法说明” `flow`、“资产操作工具” `guided`、“高级交易与恢复” `native`。这些是现有精确工具，不作为普通玩家的第八、第九主入口。

12个旧叶路由各保留一次：`builder / flow / economy / native / guided / project / manufacture / synthesis / mining / research / directory / wallet-discovery`。现有业务控制器仍只认这些原身份；一级展示名称不作为新的协议操作名。

初次打开仍可保留当前 `builder` 默认内容，对应“生物工坊→设计实验”选中。一级顺序排在前面不表示必须自动切到 `economy` 或发起数据读取。

## 2. 必须统一的词义

- `directory` 是项目一级发售目录，改为“实验室项目／浏览项目”，不能再把它单独命名“原料市场”。该页展示项目发行，真正购买仍经项目/购买模块重读。
- `project` 是创建与管理四类原料发售，不是玩家二级转卖。
- `MATERIAL` 是已发行原料的二级交易，可提供“购买项目首发原料”链接到实验室项目；两个来源要明确标识。
- `PRODUCT` 仅含部件、细胞、器官；`BIO` 仅含完整生物。分类由实际资产推导，用户改名不改类别。
- `wallet-discovery` 使用“我的资产”，其内部“当前成品／原料余额／余材／旧收益”不再统称“我的作品”。
- “生物能”对应既有LAB产出模块；整理名称不改变币种、公式、登记边界或实际领取流程。

不增加生态世界、容器、额外原料或新的奖励机制。挂牌产出规则仍按[市场规格](MARKET-SPEC-AND-NATIVE-GAPS.md)区分当前先行模式与未实现的生产体验，不由导航文案决定。

## 3. 现有导航为何不能直接换成七个普通按钮

以下是本次读取时的真实实现：

| 位置 | 现有行为 | 整理约束 |
| --- | --- | --- |
| [app.js](../apps/player/dist/app.js) `.nav-item`监听 | 非builder叶导航会取消正在运行的实验；切选中态；设置builder/flow/economy标题 | 父分组不能冒用 `.nav-item`，否则展开分组也会取消实验，空 `data-view` 还会隐藏全部内容 |
| [player-shell.js](../apps/player/dist/player-shell.js) `go(view,section)` | 搜索 `.nav-item[data-view]`，点击旧叶；可设置资产分类 | 保留旧叶DOM和唯一 `data-view`；不要把同一身份复制成父项和子项两个按钮 |
| 各 `*-operations.js`、目录和资产模块 | 各自给所有旧 `.nav-item` 注册点击监听；导航使旧只读规划/交接失效并中止迟到请求 | 真正换叶时必须走原叶点击，不能仅由新分组代码手改 `hidden` 绕过这些失效流程 |
| [asset-handoff.js](../apps/player/dist/asset-handoff.js) 及目录/发现交接 | 根据旧data-view定位目标；先填真实ID与目标页签再导航 | 新导航不能重建目标表单，不能丢目标页签，不能自动发读取或交易 |
| [app-state.js](../apps/player/dist/app-state.js) 实验runner | abort、sequence与设计generation阻止迟到结果覆盖 | 分组折叠不取消；真正离开builder按旧规则取消并保留构造；返回需重跑 |
| [test-lab.js](../apps/player/dist/test-lab.js) | 本地体验有独立pending、requestId、runId/revision及重试 | 主站会话与测试账号不互借身份；导航不清pending、不重造请求、不自动reset |

最小实施方式：一级多项分组用独立类或 `details/summary`；父项仅开关子菜单。原叶按钮仍使用 `.nav-item`。单叶一级如“协议数据”可直接使用它原来的叶按钮。“交易市场”的新页面链接使用独立类，不以空或伪造的 `data-view`混入旧控制器监听集。

若一级组选择默认子页，应只触发该旧叶的 `.click()` 一次；不要同时手动切hidden、再派发一组新导航事件。折叠当前组只影响菜单展开状态，不使当前业务页面变成未选择。程序交接到隐藏子项时，现有 `closest('details').open` 可展开其父组。

所有旧 `.view` 和表单留在当前document，按hidden切换；不要用 `innerHTML` 重建页面，也不要重新挂载同一控制器，避免输入丢失、重复监听或重复请求。

## 4. 设计草稿与独立市场页的跨文档问题

[app.js](../apps/player/dist/app.js) 的 `graph / graphTextDirty / designGeneration` 存在当前页面内存，本次读取未见跨页面保存。原12叶只切hidden，所以已应用构造、未应用JSON草稿和输入能留在原DOM；这不等于跳转新HTML后仍能恢复。

因此三个“独立市场页”须明确采用以下一种保留策略并验收：

1. 在保留工作台document的页面容器中展示独立市场内容；现有业务导航失效仍必须正确触发，不能让实验结果迟到回写。
2. 独立打开市场页、保留原工作台；不得把新页标签或测试账号当作已认证交易主体。清楚标明跨页返回方式。
3. 若同窗口硬跳，先实现仅针对非交易构造草稿的版本绑定恢复，恢复后旧实验PASS/交易intent无效。不得顺便保存私有研究salt、签名或权限到不受约束的URL/存储。

具体方式由本轮实现选择；**未处理前不能宣称跨独立页面不丢草稿。** 不要求为展开一个分组保存草稿，也不在这次导航整理中重写协议恢复机制。

旧 `go()` 是当前document内点击，不自动解释 `?view=...`。若新页面需要深链接返回主站，须新增固定白名单的路由初始化，并在全部旧叶监听就绪后调用对应旧叶；不能仅拼URL就假设它已生效。路由参数不含Actor、nonce、支付金额、graphHex或私有请求材料。

## 5. 主站与本地体验保持一致但不冒充同一能力

两个页面使用相同七类词义与三市场子类；测试页仍必须显著标“本地体验／测试数据”，实际API仍为 `/api/playtest/*`，不跳成 `/api/native/*`。主站不因新增导航而启用生产市场交易。

| 能力 | 当前可复用 | 整理后仍须明确的状态 |
| --- | --- | --- |
| 协议数据 | 主站economy；测试账户余额/账目 | 测试余额不是协议实时总量；现有经济算例不是实时行情 |
| 实验室项目 | 主站directory/project | 测试页没有完整创建发售流程时，应明确跳转主站或说明未在该体验中提供，不能模拟成已创建生产项目 |
| 生物工坊 | 主站设计/制造/合成；测试逐层体验 | 测试参考模型、原生实际流程分别标识，材料与费用不能跨模式拼账 |
| 生物能 | 主站实际规划/执行；测试时间推进 | “推进测试小时”只能在本地体验出现；导航不能触发推进、登记或领取 |
| 我的资产 | 主站真实发现；测试账号原料/成品 | 本地测试账号不是用户真实钱包；已消费祖先不能作为可售/可用资产 |
| 三市场 | 已有HOST分类、挂牌、成交、取消交互 | 独立页面与正式原子成交是不同工作；生产市场仍见M0–M7缺项 |
| 首创研究 | 主站research | 未在本地体验提供的完整首创流程不能因有链接就标为已在测试账号完成 |

本地体验的选套装、所选作品类别、三市场类别、已发起pending应保留；切换展示组不自动重新创建体验账号、重置数据或触发买卖。只有明确“重新开始”才走既有reset路径。

## 8. 本轮实施口径

主站父分组只展开，叶路由通过原监听进入；`player-routing.js`集中处理白名单hash、单页显示、标题和当前组，`market-panel.js`只读取本地能力并显示独立测试链接，不发交易。测试账号按原DOM切换七页，三市场有独立hash，工坊完成后导航到生物能。

实际桌面浏览器已逐个进入九个测试叶，余额和材料不变；完成项目购料、60→15→6→1、登记/领取/退出、BIO挂牌取消和原料买入到资产页。主站未应用JSON跨市场切换保持逐字一致。物理手机/490px真实窗口本轮没有执行，窄屏覆盖仅结构及响应CSS检查，不复用上轮旧布局截图冒充本轮。
