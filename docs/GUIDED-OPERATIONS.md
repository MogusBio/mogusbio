# BioLab 玩家操作页面与验收范围

本地首版按A1至A5推进，当前模块及最终测试数以 [实施状态](IMPLEMENTATION-STATUS.md) 为准。默认没有生产发布配置，链上规划、钱包和交易保持关闭；本机模式也不提供假余额。

## 玩家目前能做什么

工作台新增第五页“资产与购买”，分为购买原料、已有作品与历史权益两个标签。

- 购买：输入项目 ID、四类原料之一、标准单位数量和付款上限。服务端读取真实项目价格、Mint、季额/终身额、账户与当前链上时钟，给出一份精确购买草案或明确阻塞原因。当前购买表单限定付款人、租存付款人和收料人为同一 Actor，卖款归实际项目记录的收款人。
- 作品读取：输入一个已知实例 ID，读取严格校验后的 Root、RootReg 和每页最多20条真实历史 Position。项目 ID 来自项目创建记录，实例 ID 来自制造/合成记录；这里不提供完整钱包持仓索引。
- 普通质押/退出：由实际记录推导修订号、Position 序号、Directory 和事件指针；允许合法再次质押，不把旧已赚未领收益当作禁止条件。新 Position 的受益人固定。退出预约实际结束边界，不删除旧收益。此旧入口遇开放K引导至第九页的完整退出，后者提供Task/KSlot/Activation与有序结束事件。
- 历史权益：只从本页实际读到的 Position 选择一项，明确规划一步历史补记或领取已计债 LAB。领取仍付给该 Position 的固定受益人，当前 Root 所有人不能改领。没有已计债余额不代表全部历史已补完。

每次规划最多返回一个 intent。点击“送入交易检查”只会填入第四页的 Actor/intent，并切换视图；之后仍需分别准备、检查、模拟、签名和发送。读取与规划不连接钱包、不签名、不创建交易日志、不执行结算或购买，也不预留 nonce。输入、标签或视图变化会使旧草案失效。

maxPayment 限定购料协议付款，maxRent 限定原生指令分配预算；两者均不能冒充网络费与整笔交易资金充足证明。首次 LAB ATA 创建的押存可能位于原生 maxRent 之外。草案明确保留 `requiresSimulation:true`、`rentSufficiencyVerified:false` 和未报价的网络费。

## 已验收的接口

| 只读接口 | 结果 |
| --- | --- |
| `purchase-plan` | 实际自购草案、阻塞或需重新读取 |
| `asset-read` | 已知实例和有界历史页；不提供 intent |
| `asset-plan` | 普通质押/退出草案，或明确等待/阻塞 |
| `position-plan` | 一步补记/历史领取草案，或没有已计债余额等实际状态 |

四个接口沿用服务端固定发布/RPC、严格 Host/Origin/JSON/字段、规范 u64/hex、时间/大小限制与错误脱敏。浏览器不能指定私钥、RPC、发布或日志路径。只有既有显式 broadcast 路径会发送。

共享读取器已补 RuntimeEconConfig、完整 RootReg、Treasury 和 Clock。Treasury 核对真实 Classic Mint/Reserve，允许协议规定的被动捐赠和外部销毁所产生的不等式。指针在读取中变化会拒绝生成旧草案；原生执行的 nonce/修订/paid CAS 仍是最终判定。

## 验收依据与范围

525项测试包含原有核心回归及本轮读取、购买、资产、桥接和页面事件测试。购买规划能从四份实际 Bank 原始前态复现原购买 Frame/账户权限；资产规划使用原始76b真实生物检查点。替代状态和攻击场景明确是宿主测试变体，不能冒作新链上制造、质押或奖励证明。独立源码复查发现的历史 Position 与 RootReg 目录关联缺项已修复并加入回归。

本地浏览器验证了第五页、两个标签、默认关闭、历史权益区和独立交易检查入口。启用态采用模拟钱包/受限 RPC 事件和原始账本读取适配器；没有真实钱包、RPC finality、公网部署或资金广播验收。本轮没有更改原生业务、数学参数、四类原料或 LAB 经济模型，也没有增加链上机制。

全量日志：`evidence/node-implementation-p10-guided-20261025.log`。截图：`evidence/ui/guided-assets-p10-final.png`、`guided-positions-p10-final.png`。最终源码与验收汇总另存新版本，早期483项及购买 ABI 修复证据保留原身份。

## A1 项目创建与发售

第六页“创建与发售”提供精确四类条款、固定收款人、创建费及租存上限。`project-plan` 只从实际规则、Actor nonce和新账户状态生成创建草案；`project-read` 重新核对实际 Project及四个Classic Mint；`project-status` 从原持久会话恢复请求并分别展示原请求确认与实际项目记录。浏览器不能指定发布、RPC或日志。创建草案不能证明项目已创建；实际项目记录存在也不能证明一个旧nonce的执行。

严格208字节创建结果与原Frame、派生项目、四个Mint、费用上限一致后，仍须有原会话的执行证据才能显示精确确认。ALREADY_PROCESSED保留不确定性。已核验实际项目可以明确填入购买页，不自动规划或付款。输入、标签、导航和配置变化均清除旧交接数据。实际浏览器验收默认关闭的创建、记录和恢复区域；启用态用实际Bank记录和模拟页面事件验收。新增本地Bank为5笔真实签名交易，不是公网或真实钱包验收。

## A2 实际库存、固定制造与恢复

第七页“库存与制造”从已知项目和 Source 读取实际库存。最多8个项目闭包、16个Source，完整一致性批量最多93个账户；不会把浏览器余额、来源前缀或成功标志当成实际状态。原料标准单位、物种ticks、RU和LAB分开展示，已有Source是此前原料消费后的剩余物种预算，没有开包、拆解或回收。首版选择器每类使用一个足量Source，否则使用真实标准原料，不合并多个不足碎片。

`inventory-read`只读取；`manufacture-plan`以真实库存、固定F1 BOM和当前Actor nonce保存不可变公开清单，不预留材料或nonce、不创建交易请求日志。清单固定Descriptor、完整Artifact、制造nonce、Source编号、Root ID、资源及租存上限。`manufacture-next`从持久清单、实际Artifact/nonce和原会话记录最多给出一步精确intent，再明确送入交易检查。每一步仍要独立准备、模拟、签名、发送和确认。

实际序号改变不暗中重编号；已有待处理请求回到原交易恢复。原上传请求缺乏精确确认时，即使Artifact存在也保留WAIT_UNVERIFIED_PREFIX，不能猜测跳步。上传、封存和实验PASS均不等于制造。实际Root还要匹配原请求H4、Descriptor、准确debit-plan与实际Source前缀，并在返回前重读，防止旧所有权/生命周期被标成新状态。

新增22笔真实签名本地Bank交易完成两套冷启动、购买、上传、封存及制造窗口：成功部件消耗AA/NUC/LIPID/SUGAR各1份，使用14,000ticks、剩余18,000ticks，B120,000、品质1,000,000、退役45,000。原生Root和Source租存共35,628,240lamports；上传Artifact和网络费分计。这是本地默认租存及签名费结果，不能冒充目标网络报价。租存不足、后续指令失败全部业务回滚；不同blockhash同Frame重试不再烧料或制造。

制造结果108字节已从实际Bank捕获。实际成品验证与原请求精确确认分别显示；制造后Root尚属Actor且lifecycle0时，才允许明确填入“已有作品”，不自动质押。实际浏览器仅核对本地默认关闭表单与恢复布局，启用态由真实记录适配/页面事件和会话测试验收。证据见 `evidence/manufacture-a2-final-acceptance-20261025.json`。

## A3 细胞、器官与生物

第八页可从工作台明确导入规范图，再读取实际直接输入并保存公开普通合成清单。上层继承真实原始Artifact与历史叶胶囊，按实际阶段依次上传、封存、BEGIN、STEP与FINAL；不预测最终nonce或STEP次数。来源阶段和73轮功能验证分开显示。合法组合由玩家设计，子图不能被上层偷偷改写。

每步返回前核对实际依赖。FINAL读取实际LAB余额、费用、输入、旧K与新输出；成功后核新Root、子Root消费、来源并集和实际回执。输出记录核验与原请求执行确认分开。普通合成公开；它不提供首创保密。A3验收见 `evidence/synthesis-a3-final-acceptance-20261025.json`。

## A4 持续挖矿、生命周期与首创

第九页按最多4个已知实例、每件最多5条Position展示实际已处理权重、发行账、已计债/已领/待补历史。看板金额只覆盖列出记录，不是全钱包余额；未来日产量不保证。全局推进、个人补账、领取各自明确执行。完成小时只退实际原开立者押存，调用者不能改退款人。

完整退出安排K_END后ORDINARY_END，转让和合成等待真实结束与本人覆盖；旧已赚未领债权无须先领光，也不能改归新所有人。每次只返回一个意图，仍交P10.1明确准备、模拟、签名与发送。

第十页先在受保护本机目录保存私有设计和随机salt；幂等创建请求保留同一份计划。实际承诺确认且进入制造窗口后才公开上传。作者固定nonce窗口，独立推进者只用自己的nonce执行可变STEP，作者在规定窗口FINAL。未知、断窗或竞争状态不能暗中改号。Round按真实游标逐段核对；Winner认定与当前额外K资格分开。

新正式OPEN310前沿为310：原16个必备模型加上公开C310 K0。旧76b/16配置的475笔首创正例保留原身份。新67c除805笔开场分支外，已新增23,709笔同配置完整购料至普通领取/退出恢复验收；各证据不跨配置冒用，见[范围记录](../programs/transaction-transport/RESEARCH-BANK-ACCEPTANCE.md)。已知或较差模型可普通产出，不承诺首创获胜。

## 目录和钱包发现

第十一页可浏览/搜索实验室项目，第十二页按已认证钱包分别发现当前LIVE成品、历史受益Position、Source、原料ATA和classic代币提示。发现结果最多每页8条，Source/Root可保存有界ID选集并交接；已有严格读取和交易流程继续生效。覆盖和具体操作见[发现手册](DISCOVERY-OPERATIONS.md)。这不代表整个钱包的完整快照；通用组合版税和生态世界仍是后续范围。
