# 构造模式、样本来源与逐件流程差距

日期：2026-10-26。依据：本地源码只读审查。本文不修改后端、冻结生物模型、材料或经济规则，不重置测试数据，也不把修改文案当成功能实现。

修正状态：页面已明确标记C310公开样本和批量动作，当前套装进度改由kit.stage导出，费用取当前kit。第5节保留修正前的诊断；实际修正验收见[样本构造说明修正](SAMPLE-CONSTRUCTION-ACCEPTANCE.md)。逐件自由流程仍未接入测试账号。

## 1. 对玩家问题的准确回答

应当能够先制造一个部件，再选择实际部件设计并合成一个细胞，然后逐层上升。当前测试账号展示的是另一种入口：**公开 C310 参考样本的批量快捷构造**。点击一次“制造60部件”没有要求玩家逐件设计；后台按固定目录逐件制造60件，再把它们作为一套显示。

这60件在HOST账本中确实消费材料并产生独立实例，不是凭空送出；但“不是凭空”不等于“玩家已经自己设计”。启动时已有的60件还属于预备参考样本，不应冒充本次操作成果。当前自由工坊的核心模块与快捷测试账号也不是同一套已打通的用户流程。

## 2. 三种入口必须分清

| 模式 | 材料与成品从哪里来 | 玩家设计了什么 | 当前状态 |
| --- | --- | --- | --- |
| 预备参考样本 | 启动前按模型购料、逐件制造60部件、结算收益、退出、领取；另外留一套原料 | 尚未由当前玩家设计 | 已实现，用于避免首次体验长时间准备；必须明确标样本 |
| C310参考快捷构造 | 玩家选择套装，批量执行既有制造/合成模块，原料和旧实例实际消费 | 使用固定公开C310图；当前接口不接自定义图 | 已实现HOST路径；应明确标“按参考样本批量制造/合成” |
| 玩家逐件设计与构造 | 自选单件部件、真实输入实例与合法图，逐个保存清单、验证和产出 | 冻结模型允许的连接、比例、能力、布局、层级模式 | 主站核心模块已有；测试账号内完整逐件交互尚未接通 |

这三个模式都不得说成任意蛋白折叠设计或真实生命制造已经实现。

## 3. 主站已经能做的单件与自由设计

| 模块 | 源码核实的能力 | 固定边界 |
| --- | --- | --- |
| [部件制造页面](../apps/player/dist/manufacture-operations.js) | `manufacturePlanRequest`每份清单只有一个descriptor，保存后按UPLOAD/SEAL/MANUFACTURE推进，实际Root核验后可交接 | 没有“数量60”字段；仅primitive1..4，类型1–3 profile0，类型4 profile1..15 |
| [部件描述编码](../packages/composition/src/payload.mjs) | `descriptorBytes/decodeDescriptor`验证固定原语版本、类型和用途profile | 没有氨基酸序列、任意酶参数或新物理规律字段 |
| [主站设计实验](../apps/player/dist/app.js) | 从公开参考开始修改；运行实验；通过后交接到合成；失败保留构造 | 本地实验PASS不是材料、成品或奖励；未应用JSON草稿不能拿旧PASS继续 |
| [点选编辑器](../apps/player/dist/visual-designer.js) | 编辑合法N/O/W连接和比例，交换15格位置，选择固定A/B层级模式；工作台还能调整允许的能力值 | 自由度受固定端口、树、必经边和容量限制，不能添加任意原语/细胞类型 |
| [合成页面](../apps/player/dist/synthesis-operations.js) | 选择一个target与直接输入，导入当前图、读取实际输入、保存不可变清单，推进验证并核验一个新Root | 一次一个细胞/器官/BIO；原始Artifact、输入ID、revision、来源、图和费用一起绑定 |
| [组合协调器](../packages/composition/src/coordinator.mjs) | 实际材料消费、固定BOM、输入所有权/可移动性、图验证、品质计算、费用与旧实例消费在同一提交边界核对 | 子作品设计与来源必须继承，不能换名字复用已消费实例；历史收益仍按原受益人保留 |

F1固定部件使用同一BOM；`manufactureComponent`要求消费14,000物种ticks，形成有效120RU及退役45RU，对应内部整数credit。原料Token按整份摄入，未用物种留在Source前缀预算；不能把整条链的平均份数当成可交易的小数原料，也不能据此拆回成品。

当前层级固定为：

- 一个功能细胞：四件符合用途的实际F1部件，类型1、2、3、4各一件。
- 六种器官：分别使用固定角色组合的2、3、4、2、2、2个细胞，共15个功能细胞。
- 一个完整生物：六个匹配的实际器官。

来源分别见[固定树和图校验](../packages/biology/src/graph.mjs)的 `ORGAN_CELLS/members/validateGraph` 与合成页面的 `counts/checkedSynthesisInputs`。完整标准链是60部件→15细胞→6器官→1生物；这是功能模块尺度，不是现实一比一细胞数量。

自由设计不是只换参考名称，但也不是无限自由：自由连接必须落在规定的物流类型/端口；固定边不能删改；能力、布局、层级模式有合法范围，验证还要通过供能、控制、负载、障碍与恢复等73轮。器官/BIO不能把已有子图的内部参数静默改掉。

## 4. 为什么测试页一下产生60件

[测试运行时](../apps/playtest/runtime.mjs)的实际调用链：

1. `manufacture(state, kit)`循环15个角色，每角色循环primitive1..4。
2. 每次调用 `manufactureOne`；按当前nonce、业务ID和真实HOST库存运行 `planComponentMaterials`。
3. 调用既有 `composition.manufactureComponent`，消费固定BOM，产生一件独立Root。
4. 成功完成60次后，记录这组ID为套装部件；页面只显示一次批量动作的摘要。

`execute`先克隆本次状态；任一步失败即恢复整次操作前状态。因此它是“一次点击触发60次固定制造”的HOST快捷操作，不是跳过材料规则，也不是60笔实际Solana签名交易。ROOT、Token和费用结果仍须和账目一致。

合成同样使用批量包装：细胞按钮逐个合成15个目标，器官按钮逐个合成6个目标，BIO按钮合成一个目标。每次 `makeParent`固定使用：

```text
fullGraph = createPublishedC310Graph(...)
graph = projectGraph(fullGraph, target)
composition.prepareSynthesisPayload({graph, inputIds})
upload / seal / composition.synthesize
```

源码中的 `makeParent`固定挑战参数，并执行既有验证和费用；玩家不是在这一步选择自己的图。需要清楚展示“公开C310参考样本”，不能仅写“自由构造成功”。这条路径不生成新首创资格。

启动预备流程 `buildReady`购入两套标准原料，将第一套按上述相同制造链变成60件部件，进行历史登记、结算、退出和领取，再把该状态作为体验起点。剩余120份原料与预备60件是独立库存。完整新参考链用30AA／60NUC／15LIPID／15SUGAR，共120份，升级销毁48LAB；参考快捷入口不能额外赠送原料或免合成费。

## 5. “五步都已体验”的显示问题

本次读取的[测试页控制器](../apps/player/dist/test-lab.js)在 `render` 中使用：

```text
done = new Set(state.ledger.map(row => row.action))
```

它读取全账户最近30条动作类型，而不是当前套装的制造记录。例如套装A完成五种快捷动作后，选套装B的RAW阶段，也会继承A的五种“已体验”；更早记录被截断后又可能丢标记。[运行时](../apps/playtest/runtime.mjs)的 `log` 也没有为每条普通历史直接保存kitId，不能把这份全局动作集合当成逐套装完成证明。

这不会凭显示直接增发材料或奖励，但会误导玩家，以为当前作品是自己逐件制作并设计完成。修正要求：

1. 当前套装进度从规范 `kit.stage`及真实可用性导出，显示“已到达／当前／未到达”；不要宣称玩家亲自执行过每个此前阶段。
2. 预备部件明确叫预备参考样本；参考快捷按钮明确列出本次批量数量与C310来源。
3. 账户历史与当前套装进度分开。需要逐件历史时，未来必须有逐件实例/输入/输出/请求的可核关联，不能仅靠颜色或动作名。
4. 只调整展示或必要记录模型，不删除已有账本、不reset测试账号、不重造runId、nonce或pending请求。本次文档没有进行任何数据迁移。

本节记录审查时的问题，不替代根任务的UI修正验收。

## 6. 测试账号真正逐件自由流程还缺什么

[HTTP白名单](../apps/playtest/http.mjs)当前只有 `manufacture-kit / synthesize-cells / synthesize-organs / synthesize-bio` 等批量动作；对应参数仅kitId。不能只把按钮改成“制造一个”或展示一个编辑框，就宣称底层已经接通。

| 顺序 | 待补能力 | 复用什么与验收条件 |
| --- | --- | --- |
| 1 | 明确模式入口 | “自己逐件构造”与“参考样本快捷体验”独立；保留预备样本但不自动当玩家作品 |
| 2 | 测试账号单件制造 | 固定primitive/profile点选、材料预算与费用预览；复用BOM/Source/nonce与消费；一次只新增一件实际Root，失败无业务扣减 |
| 3 | 选择四件实际部件 | 按角色匹配、自有、LIVE、未托管/未锁、未消费筛选；重复ID/缺件拒绝，不由UI补造输入 |
| 4 | 用户设计图接入测试库存 | 明确导入主站编辑图或同页编辑，绑定版本/target和精确图摘要；不在后台静默改回C310；非法图失败仍保留草稿 |
| 5 | 单个细胞合成 | 读取四件真实输入，逐轮验证，显示实际品质，确认只消费四件并产生一个细胞；未选的其他部件保留 |
| 6 | 单个器官/BIO合成 | 继承真实子图/来源，按固定2–4细胞或6器官构成；改变高层设计仍满足子图继承与容量规则 |
| 7 | 逐件账目与恢复 | 每步关联实例、材料前缀、费用、图、验证与输出；精确requestId重试、并发CAS、跨页/重启恢复，未知结果不能另造一次 |
| 8 | 设计→成品→产出 | 本地实验不计权；只有实际合成成品登记后按现有小时规则参与LAB；父子未来权重不重复，旧收益不丢 |

这些是测试账号与现有模块之间的产品/API接线缺项，不表示主站所有制造/验证核心都要重写。主站原生规划与HOST测试动作也不能共用未经核验的Actor身份，不能用本地测试结果冒充链上成品。

批量快捷功能可以保留为可选加速入口，显示本次制造/合成数量、使用的参考图和总材料/费用。它应复用同一逐件规则；不得作为替代逐件玩法的默认唯一能力，也不能伪装成玩家自由设计。

## 7. 后续完成口径与验收

- 本次已确认：预备样本、参考批量构造、固定F1部件、主站自由图及逐个合成核心的真实范围。
- 本次未实施：测试账号单件动作、自定义图制造/合成接口、逐件构造UI及对应完整验收。修改样本文案后仍不得说自由工坊已全部完成。
- 逐件验收至少应跑：造一件→库存减少且只出一件；造齐四件→修改合法连接并验证→只合成一个细胞；非法图/缺件/重复实例回滚；继续到器官/BIO；过程中刷新/超时原请求恢复；参考模式与逐件模式分别计账。
- 所有显示修复都应保持现有测试账号数据与未确认操作，不为得到“干净截图”重置玩家进度。

已有测试体验说明见[本机点击指南](LOCAL-CLICK-PLAYTEST.md)。本文只读核查与文档更新，没有重新生成参考账本、执行制造、推进小时或发起任何链上交易。

## 8. 公开参考数量与自由范围

当前公开参考共17个：16个开场必备设计加公开C310。依据是主站`apps/server/main.mjs`的references构造及OPEN310公开种子；其中两个参考同为C330但设计不同，不能按成本数值去重。17个参考不是可合成构造的白名单。预置账号的批量体验只接C310这一个固定图。

冻结模型内，玩家自定的合法图可以通过完整验证并产生独立成品，参考以外的设计也可以合成。首版部件原语、15个功能角色、6种器官分组及完整生物骨架仍固定；自由度包括允许的连接、比例、能力、布局与层级模式。当前不支持无限新增原语、任意细胞数量或任意真实生物物种。合成成功不自动获得首创奖励，首创还要求新颖性和任务改进。

主站已有规则内设计、验证、单件制造和逐目标合成模块。测试账号尚未接通自定义图和单件动作，不能说玩家现在已经能在这个批量体验里逐件自由走到生物。第6节仍是后续产品/API接线缺项，不应把样本提示修正当成新流程实现。
