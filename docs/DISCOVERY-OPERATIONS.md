# 实验室目录和钱包资产发现

目录和资产发现是链上记录的只读入口。它们按当前发布、部署域和配置读取项目、成品、原料及历史受益权，不依赖玩家手填一串已知ID，也不把本机操作日志当成全链资产索引。发现结果可以交接给已有页面；购买、制造、合成、质押或领取仍须先重读其完整依赖，再明确签名。

## 新OPEN310基础链

新67c程序已经在同一个OPEN310配置中，从空账本完成23,709笔真实签名Bank交易：17模型预热、四类购料、60部件→15细胞→6器官→公开C310生物、普通质押、小时结算、退出、领取和最终END推进。逐包Ed25519复核、失败回滚、缓存重试和三次重启均有独立记录。

实际账目为30/60/15/15份原料、48 LAB制造销毁、49.024940 LAB总领取、1.024940 LAB末余额。全部61份历史Position已结束、覆盖到结束边界且全额领取，全局活动权重归零。公开C310只有普通奖励，没有新Winner/K。详见[完整验收](../programs/transaction-transport/OPEN310-FULL-LIFECYCLE-ACCEPTANCE.md)。

后续发现验收直接使用该配置的原始终态：82个Root中1个LIVE、120个Source和61个Position。HOST读取适配器保留原始账户字节；它对RPC过滤和响应的模拟不冒充公网索引或finality证明。

## 发售目录

1. 明确签署站点登录消息。目录使用当前已验证的登录Actor，不允许网页另选私有钱包主体。
2. 进入“实验室发售目录”，选择全站项目或自己创建的项目，开始有界扫描。可按项目名称、完整项目ID或创建人地址搜索。
3. 结果只展示本页已核验项目与四类mint条款。`issued / cap`是该项目的发行记录，不是当前可购量；全网季额、价格和付款上限由购买规划重新核对。
4. 选择项目后，填入“创建与发售”的项目读取页，再明确重读四个mint，然后交接到购买页。交接不会查询、付款、预留nonce或连接钱包。

搜索贯穿服务器的分区遍历，不只过滤当前显示的八条。扫描按账户类型和不可变ID组织，不代表全网最新创建时间排序。没有匹配记录但仍有待扫描工作时，可以继续；查询失败不能解释成“没有项目”。

## 我的BioLab资产

各分类分别读取，分别说明覆盖进度，不合并成一个可支出的总余额。

| 分类 | 实际含义 | 后续操作 |
| --- | --- | --- |
| 当前成品 | 当前Actor拥有的LIVE部件、细胞、器官、生物；已消费祖先不列为现有资产 | 填入已有资产/挖矿读取页，或选择合成输入ID后明确重读 |
| 历史受益权 | Position固定受益人是当前Actor；关联成品可以已转让或已消费 | 按实际实例和Position序号进入历史读取；不能把K再重复加一次 |
| 余材记录 | Source原始摄入与32种物种的已用、剩余前缀 | 选择最多16个Source、最多8个项目的ID，交接给现有库存读取 |
| 原料ATA | 发现实际项目后派生并核对当前Actor的四类标准ATA，显示正余额 | 选择项目进入实际库存读取；不直接授予制造能力 |
| Classic代币提示 | 有界钱包Token账户读取，固定LAB mint可识别；其他mint仍可能未识别 | 仅提示，不自动纳入制造或当成领取资格；非ATA不合并到ATA制造库存 |

Source的`unitCount`是历史摄入份数，不是还可用的标准原料。标准参考链有120个Source，总历史摄入120份；原料Token已销毁后，不能把这120再加回余额。剩余物种总计300,000 ticks，能否组成某个新部件仍由固定BOM和完整库存重读决定，没有拆解或回收。

Source选集只保存ID，最多16个唯一来源及8个项目。合成待选集只保存最多6个当前LIVE成品ID。选集可跨同分类的分页保留；重新扫描、切换分类、导航或身份/配置变化会清除。交接后仍由原有inventory-read或synthesis-inputs重新核对所有权、消耗状态、层级与容量；发现页面不自报“可以制造/合成”。

## 分页和覆盖

独立`DiscoveryRpc`仅执行固定的只读发现查询，原有`ReadOnlyRpc`的权限表保持不变。桥接只接受`{actor, section, cursor, query}`，不能指定RPC、程序、过滤器、前缀、路径或预算。所有私有分类都由网关认证Actor；同钱包会话共享只读扫描，不产生新的交易日志。

- 每页最多8条。先按类型/发布上下文/Actor做32字节ID切片的小探测；只有响应溢出才按不可变ID前缀细分，避免空站点或标准120条Source也固定扫描256个空分区。
- 切片响应最多64KiB、少于256条候选。每页最多4次扫描、3次批量完整账户读取和1次genesis校验；全页18秒，每次RPC最多2秒。完整行在PDA、Header、原生数据及依赖闭包核对和最终重读后才展示。
- 记录按`finalized`读取，返回观测slot范围。多页是多个时点的观察；转入已扫前缀或扫描期间的变化可能要刷新才能发现。`TRAVERSAL_EXHAUSTED`只说明本次范围遍历结束，不是某一瞬间的密码学完整快照。
- RPC错误、超时、索引不支持、字段错误或重读变动均不当成空集合。有效继续标识可重试；过期或不匹配的标识明确要求重新扫描。
- 标准SPL owner查询没有可保证完整分页的唯一数据ID。超出预算时返回OVERFLOW，不编造后续页；这不阻止独立的协议ATA发现继续。

离链扫描缓存TTL为30分钟，每个Actor最多4个未完成分类，全局最多128个保留扫描；单扫描最多256KiB、聚合最多8MiB。已完成缓存不占Actor活动额度，重复刷新同一分类替换旧扫描，不因刷新四次锁住玩家。只保留有界候选和上一页响应，没有永久链上收据或额外SOL租存。

缓存绑定完整发布上下文、Actor、分类、查询和可信RPC。更换RPC时只更换发现缓存命名空间，旧标识要求重扫；业务nonce和交易恢复日志继续使用原来的发布命名空间。

## 本地预览与真实环境

显式离线预览命令：

```text
node scripts/preview-discovery-local.mjs --local-public-fixture --demo-wallet
```

它只监听本机，读取新67c捕获账本，使用已公开的本地消息签名测试身份，不能签署或广播链上交易。关闭终端后删除本次临时认证和扫描状态，不触及原始验收账本。正常站点不会提供这些测试钱包脚本或配置路由。

正式接入仍须核对实际RPC是否开放所需索引、目标钱包、HTTPS代理、多用户负载、费用与恢复表现。发布身份、外部服务签名器和托管条件尚未绑定；本次没有上线。
