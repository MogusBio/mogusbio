## Intended behavior

Add a server-owned read/plan layer for asset lookup, ordinary stake, exit, historical reward accrual, and claim. Transfer constraints are included because asset lifecycle and exit eligibility depend on the same registration facts; exposing a transfer form is a separate implementation choice.

The planner returns actual finalized facts and, when all relevant gates pass, at most one unsigned intent. A separate explicit browser action transfers that intent into the existing P10.1 console. The user must still prepare, inspect, simulate, sign, and send in separate steps. Planning never signs, journals, sends, reserves a nonce, advances settlement, or executes another action automatically.

The server retains the P10.1 trust boundary: release, ABI, endpoint, journal directories, and fixture policy come from its trusted configuration. Browser requests cannot override them. All integers that may exceed JavaScript's safe integer range use canonical decimal strings. Reject unknown fields and malformed or unsupported records.

## Existing reusable code

- [ReadOnlyRpc](../packages/client/src/rpc.mjs) verifies the configured genesis, uses finalized `getMultipleAccounts`, enforces monotonic context slots, and bounds response/account bytes.
- [Native account decoders](../packages/client/src/accounts.mjs) already cover BaseConfig, Root, Registry, Position, Directory, Hour, Activation, and Classic SPL token/mint records.
- [Native encoders](../packages/client/src/native.mjs) include `encodeRegisterOrdinaryPayload`, `encodeExitOrdinaryPayload`, `encodeTransferRootPayload`, and `encodeClaimPositionPayload`.
- [Personal settlement coordinator](../packages/client/src/player-settlement.mjs) plans actual claim/accrue steps and exports `nativeActionIntent`.
- [Settlement planners](../packages/client/src/settlement-workflow.mjs) construct lazy accrual, accrued claim, frozen-hour advance, and final-hour close actions.
- [LAB destination setup](../packages/client/src/lab-destination.mjs) constructs the fixed official idempotent ATA setup; [NativePlayerSession](../packages/client/src/session.mjs) independently checks its Position beneficiary before prepare/broadcast.

These pieces do not constitute complete guided operation eligibility checks. In particular, the existing claim planner does not read LABMint, LABReserve, Treasury, and RuntimeEconConfig before constructing its action.

## Missing strict readers

- [ ] Shared `decodeNativeRootRegistration` and `getRootRegistration`.
- [ ] Runtime `bio/econ-config` decoder and reader: kind36/schema3, 424 total bytes, canonical release header and 304-byte `ECOCFG03` body. Validate release/bootstrap/mint/reserve/auth identities, fixed supply/decimals, validator/rule hashes, initialization time, published schedule/prewarm, and initial seed set. `verifyBaseConfig()` reads a separate BaseConfig and does not prove economy initialization. Native gate: [accounts.rs](../programs/biolab-economy/src/accounts.rs), `config`.
- [ ] Shared strict Clock decoder and reader: canonical Clock address, Sysvar owner, non-executable, exactly 40 bytes, nonnegative timestamp, slot and timestamp suitable for comparison with actual Root/Registry/Task facts. Existing keeper/settlement functions contain private Clock readers that can be consolidated.
- [ ] Treasury decoder and reader: kind6/schema1, canonical `bio/treasury` PDA, 184 total bytes, release domain/config and config-ID record key, eight LE u64 fields. Native gate: [accounts.rs](../programs/biolab-economy/src/accounts.rs), `treasury`.
- [ ] Optional canonical account reads distinguishing nonexistent records and system-owned, non-executable, empty prefunded shells from malformed or unsupported accounts. Never convert a malformed account into a blank registration.
- [ ] Task and KSlot decoders/readers for the actual K-aware exit branch. An Activation decoder already exists, but full Task/KSlot/Activation cross-link validation does not.
- [ ] Read-driven stake, exit, and optional transfer planners; stronger economy-account reads for guided claim and cold-prefix stake.
- [ ] If the interface claims rent sufficiency, add verified rent inputs/readers. Existing Root decoding omits the native Root rent-exemption check. Do not hardcode rent constants or describe explicit `maxRent` as proven transaction affordability. Native gates: [root.rs](../programs/biolab-economy/src/root.rs), `read_root`; [accounts.rs](../programs/biolab-economy/src/accounts.rs), `need_rent` and `check_budget`.

Every native record reader must validate owner, non-executable state, exact admitted kind/schema/length, magic/version/reserved bytes, release domain/config, canonical PDA/bump and record key before interpreting its fields.

### RootReg body and invariants

RootReg is kind25/schema1, canonical `[bio,root-reg,instance]`, 380 total bytes / 260 body bytes. Offsets below are relative to the body, after the 120-byte native header.

| Body offset | Field |
| ---: | --- |
| 0 | instance32 |
| 32 | registrationRevision u64 |
| 40 | ordinaryCount u64 |
| 48 | lastPositionId32 |
| 80 / 81 | ordinary end tag u8 / end u64; tag0=open, tag1=closed |
| 89 | K activation count u64 |
| 97 | lastActivationId32 |
| 129 / 130 | K end tag u8 / end u64; tag0=open, tag1=closed |
| 138 | coverageSequence u64 |
| 146 | nextCoverageHour u64; MAX sentinel |
| 154 | first permanent revocation cause u8, 0–3 |
| 155 / 187 / 195 | revocation business32 / timestamp i64 / slot u64 |
| 203 | certificateFault tag u8 |
| 204 / 236 | certificateFault business32 / event u64 |
| 244 | lifetime directorySequence u64 |
| 252 | reserved former scan cursor u64, must be zero |

- [ ] Mirror all native `root_reg` invariants in [settlement.rs](../programs/biolab-economy/src/settlement.rs): coverage≤count, canonical end tags and zero sentinels, canonical revocation/fault facts, and reserved cursor zero.
- [ ] A count-zero record has directory MAX, zero last Position, and canonical closed ordinary state. A count-positive record binds its last Position ID to sequence count−1.
- [ ] coverageSequence==ordinaryCount requires nextCoverageHour MAX.
- [ ] A proven absent canonical RootReg may supply the native first-registration defaults for planning, but the response must retain `exists:false`; do not present an invented stored record.

## Native operation gates

### Stake / REGISTER_ORDINARY

Native source: [settlement.rs](../programs/biolab-economy/src/settlement.rs), `stake`.

- [ ] Actor is an on-curve, system-owned, non-executable empty wallet account and owns the live Root at its actual revision. The Root decoder validates schema, quality and material base; ordinary weight is derived from these actual facts.
- [ ] Read actual Clock and initialized RuntimeEconConfig. Clock cannot precede Root creation timestamp/slot or Registry seconds high-water.
- [ ] Derive `positionSeq = RootReg.ordinaryCount`; only proven absence permits zero.
- [ ] For first registration, derive `directorySeq = Registry.rootCount`; for later registrations use RootReg's lifetime directorySequence. Missing Registry can use native empty defaults only after its canonical address is proven absent/fresh.
- [ ] Require certificateFault absent, K closed, and actual current boundary≥K end.
- [ ] Restake additionally requires ordinary closed, actual boundary≥ordinary end, and the actual previous Position count−1 ended at exactly that recorded end.
- [ ] Derive start=0 before rewardStart, otherwise actualBoundary+1; require start<H_END. Beneficiary is an explicit nonzero public key and becomes immutable for the new Position. Default the form to Actor; clearly show a different selected beneficiary.
- [ ] New Position and START Event are canonical fresh PDAs; event sequence is actual Registry.eventCount. The first Directory is fresh; an existing Directory validates its immutable instance identity.
- [ ] CurrentHour is exactly Registry.nextHour. Never accept an arbitrary current-hour pointer from the browser.
- [ ] First-ever global stake mirrors the native cold-prefix proof: synchronize the actual Treasury book against completed hours, preserve older lazy Pending budgets, check zero certified debt and sufficient pending amount, and validate any existing current Hour's required empty-ready facts. Do not omit this branch.
- [ ] Validate event ordering/frontier facts and all counter/revision increments for overflow.

Historical coverage completion is not a restake requirement. Directory.active must not be used to prohibit restake while ordered END/START events await replay. Permanent K revocation also does not prohibit ordinary staking; native stake checks certificateFault rather than revocation cause.

### Exit / EXIT_ORDINARY

Native sources: [settlement.rs](../programs/biolab-economy/src/settlement.rs), `exit`; [originality.rs](../programs/biolab-economy/src/originality.rs), `exit_with_k`, `prepare_stop`, and `commit_stop`.

- [ ] Derive the latest Position sequence from actual ordinaryCount−1. Do not ask a beginner to invent it.
- [ ] Require live owned Root at actual revision, no certificateFault, ordinary open, exact last Position link/directory, rewardStart reached, and actual current boundary≥Position.start.
- [ ] A newly scheduled stake cannot immediately exit before its start boundary. Display a waiting state instead of constructing an invalid intent.
- [ ] Ordinary exit end is actualBoundary+1. Its queued reward event clamps to H_END, but the physical end lock retains the actual boundary.
- [ ] Without open K, use the exact ordinary fixed suffix and end event at actual eventCount.
- [ ] With open K, validate Task, KSlot and Activation, including current activation ID, RootReg K count/end linkage, ordinary Position ID, beneficiary/author, and Task/Clock high-water facts. Append Task/KSlot/Activation/KEndEvent. K end uses eventCount; ordinary end uses eventCount+1. Match the native combined-rent branch.
- [ ] Until the K-aware branch exists, return explicit `K_AWARE_EXIT_REQUIRED` with no action. Never silently omit K accounts or substitute ordinary-only exit.

The form should explain that exit schedules an end at the next eligible boundary. It does not withdraw an asset token or erase historical rewards.

### Transfer / TRANSFER_ROOT

Native sources: [settlement.rs](../programs/biolab-economy/src/settlement.rs), `transfer`, `assert_movable`, and `mark_revoke`.

- [ ] Exact owner/live Root revision and actual RootReg revision; zero registration revision is allowed only for a proven absent canonical registration.
- [ ] New owner is distinct, on curve, nonzero, and excludes program/token/system addresses.
- [ ] Ordinary and K are closed; both actual physical end boundaries have passed.
- [ ] coverageSequence==ordinaryCount and nextCoverageHour==MAX; no certificateFault.
- [ ] Use uncapped actual boundaries after H_END, rather than capped completed reward hours.
- [ ] Preserve an existing permanent revocation cause. Payment of historical accrued debt is not required for transfer and transfer must not redirect that debt.

### Historical claim / CLAIM_POSITION

Native sources: [position.rs](../programs/biolab-economy/src/position.rs), `position` and `claim`; [token.rs](../programs/biolab-economy/src/token.rs), `mint` and `token`; [accounts.rs](../programs/biolab-economy/src/accounts.rs), `treasury`.

- [ ] Reread the selected Position and canonical beneficiary ATA together with LABMint, LABReserve, Treasury, RuntimeEconConfig, and relevant common state.
- [ ] LABMint: canonical PDA, Classic SPL owner, non-executable, 82 bytes, initialized, decimals6, absent mint authority and freeze authority.
- [ ] LABReserve: canonical PDA, Classic SPL owner, non-executable, 165 bytes, LAB mint, canonical LABAuth token authority, initialized/unfrozen/non-native, no delegate, delegated amount zero, no close authority.
- [ ] LABAuth is a canonical signer PDA address. Do not invent an account owner/data/existence requirement absent from the native handler.
- [ ] Treasury: checked sum of book fields0–3≤reserve; burned≤N; mintSupply≤N−burned; reserve≤mintSupply; reserved field7 zero. These are inequalities: unsolicited reserve transfers remain sealed, and external burns may reduce supply.
- [ ] For amount=upper−paid, require paid≤upper≤actual accrued, certified debt/reserve≥amount, and destination balance plus amount and cumulative paid-total plus amount fitting u64. Beginner default upper is actual accrued.
- [ ] Existing destination is a valid Classic SPL token account for LAB and immutable beneficiary, differs from reserve, and satisfies native token state checks. Reserve-only delegate/close restrictions must not become extra destination restrictions.
- [ ] Missing or system-owned, non-executable, empty canonical ATA may use existing official idempotent setup. Wrong owners, Token2022/extensions, wrong mint/beneficiary, and frozen accounts fail closed.
- [ ] **Native maxRent covers native nonce allocation, not the preceding ATA setup rent.** Display ATA rent and network fee separately; do not call maxRent a total transaction spending cap.
- [ ] Current Root ownership/lifecycle, Registry membership, and historical coverage completion are not claim authorization requirements. Claim is a permissionless trigger paying the saved beneficiary.

`NO_ACCRUED_DEBT` does not prove all historical hours were settled. Provide an explicit accrue choice using the actual Position and existing coordinator, retaining `WAIT_PRIOR_POSITION`, `WAIT_FROZEN_FRONTIER`, and `COVERAGE_COMPLETE`. One accrue plan advances only one real eligible step; it does not silently loop until a claim is possible.

## Proposed read-only planner interface

Endpoint names are proposals, not implemented API contracts. Each variant must have an exact request schema, reject unknown fields, and enforce existing body/time/response limits.

### Asset read

Proposed request: `POST /api/native/asset-read` with `{actor,instanceHex,positionPageStart,positionPageLimit}`. Instance is an exact 32-byte hex ID; page values are validated, and page limit is bounded, for example at 20 Positions.

The response contains finalized context slot(s), verified Root/RootReg/Registry/Clock facts, a bounded page of strictly decoded actual Positions, pagination information derived from the real ordinaryCount, explicit existence states, and reasons that particular actions are unavailable. It contains no fabricated Position counter or promised future reward.

Start with known-ID lookup. Wallet connection and ActorNonce do not provide a complete holdings index. A bounded selected-ID reader must not be labeled “all my assets.” Complete discovery needs a separately designed bounded/indexed data source with explicit coverage guarantees; an unbounded `getProgramAccounts` scan must not silently become the default browser flow.

### Action plan

Proposed request: `POST /api/native/asset-plan`, with common `{actor,instanceHex,kind,maxRent,resources}` and an exact discriminated variant:

- `stake`: additionally `beneficiary`.
- `exit`: no browser-supplied position/revision/event/directory counters.
- `transfer`, if exposed: additionally `newOwner`.
- `claim` or `accrue`: additionally `positionSeq`, selected from a previously read actual Position. Server independently rereads and validates it.

`maxRent` and priority fee are canonical decimal strings; the existing four resource fields remain explicit. ActorNonce, Root revision, registration revision, Position paid CAS, event sequence, Directory identity, and settlement cursors are never accepted as eligibility assertions from the browser.

Every result returns `clientPlanOnly:true`, `transactionExecuted:false`, finalized observation information, and an exact decision. Blocking/waiting decisions return facts/reasons and **no intent**. `ACTION` returns at most one `nativeActionIntent`, its operation, observed nonce, immutable recipient/beneficiary, relevant state/CAS summary, and explicitly marked preview values. Nonce comes from actual finalized ActorNonce, is displayed, and remains unreserved.

The browser offers “Use this reviewed intent” only for the current unmodified `ACTION` result. Clicking it fills Actor and intent in P10.1; it does not call prepare or open a wallet prompt. Any change to Actor, instance, selected Position, action, beneficiary/new owner, rent, or resources aborts pending work and invalidates the previous result and transfer button, including while the first request is still in flight.

## Pointer races, rereads, and execution CAS

- [ ] First read discovers actual counters and pointers; derive dependent account addresses on the server.
- [ ] Fetch the selected accounts together in a final finalized `getMultipleAccounts` batch at a monotonic `minContextSlot`. Include all state that determines the action, including the appropriate actual ActorNonce account and Clock.
- [ ] Fully decode the final batch and compare discovery-dependent facts: Root identity/revision/owner/lifecycle; registration count/revision/last Position/directory/K state/coverage; Registry event count and current Hour; Position beneficiary/accrued/paid/end/next hour; and K pointers where applicable.
- [ ] If a pointer changed, return `REPLAN_STALE_STATE` with no intent, or perform a separately bounded reread policy. Do not derive one account from an old pointer and claim the result is one coherent snapshot.
- [ ] Validate paired identities even when individual records decode: RootReg↔Position↔Directory, KSlot↔Activation↔Position, and Hour K beneficiary/Position linkage.
- [ ] A finalized read remains advisory. The nonce can advance and paid/revision/cursor facts can change after planning. Native prepare/session checks, simulation, signature verification, and on-chain CAS remain authoritative.
- [ ] Never reserve, renumber, retry, prepare another operation, replay settlement, claim after accrue, or execute a cancellation automatically. Surface explicit stale/wait/unknown results to the user and preserve the P10.1 original/cancellation separation.
