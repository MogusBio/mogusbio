# 模块积木与修改顺序

Devnet扩展按传输/部署、原生市场、读取外形、私有恢复、运营服务和玩家交互分层；变更入口与引用关系见 [Devnet模块表](DEVNET-RUNBOOK.md)。冻结核心ABI `operations.p0r2.json` 保留；新增市场ABI只允许精确Devnet发布引用。改经济/模型须另立版本，不能靠UI或服务改变权重/排放。

这份表是后续修改的入口，不是新的经济或生物规则。先查已有模块与接口，再改动；不把测试账号规则当作生产协议。当前497文件源码及992项本地回归的范围见 [本轮验收](CLICK-PLAYTEST-ACCEPTANCE.md)。

## 一、各块负责什么

| 块 | 现有位置 | 负责的数据与决定 | 不能代替谁 |
| --- | --- | --- | --- |
| B0 编码与材料 | `packages/protocol-core` | 精确字节、目录、nonce、整数单位、实际材料消费 | 页面文字不能增发或制造材料 |
| B1 一级发售 | `packages/launchpad` | 实验室、四Mint、价格、发行额度、付款交付、Ops | 不能把转卖算成新发行 |
| B2 生物规则 | `packages/biology` | 图、端口、容量、逐轮作用、品质、设计ID | 预测或蓝图不等于已制造资产 |
| B3 制造与合成 | `packages/composition` | Artifact、真实输入继承、成品、单向消费、制造销毁 | 不能从UI套装名称凭空补齐输入 |
| B4 持续产出 | `packages/settlement` | 登记、小时边界、权重、债权、领取、退出、守恒 | 市场或页面不能自己算一份可领奖励 |
| B5 首创 | `packages/originality` | 承诺、披露、候选、前沿、额外资格 | 转售和复制不产生新首创 |
| B6 真实执行 | `programs/biolab-economy`、`packages/client` | 原生账户、ABI、签名、模拟、原子执行、原请求恢复 | Node参考计算不能冒充已广播确认 |
| B7 权限与服务 | `packages/bridge`、`apps/gateway`、`apps/service` | Actor、会话、发布身份、受限桥接、预算、持续服务 | 后台不能替玩家授权卖出或改价 |
| B8 玩家页面 | `apps/player/dist` | 点选、下一步、已验证状态、显示与交接 | 不决定库存、品质、权重或资产归属 |
| T0 本地测试编排 | `apps/playtest/runtime.mjs` | 用既有B0–B5模块串起体验，明确测试System/rent适配 | 不能进入生产操作的授权路径 |
| T1 本地市场 | `apps/playtest/market.mjs` | 三市场分类、现有资产托管、测试报价、原子买卖 | 不是已经完成的正式Solana市场 |
| T2 本地账户接口 | `apps/playtest/http.mjs` | 隔离cookie、持久化CAS、revision、requestId、重置代次 | 不接受客户端余额、价格、owner或后端替换 |
| T3 本地界面 | `test-lab.js`、`test-market.js` | 构造引导与市场分别渲染，自动传递选中ID | 页面按钮隐藏/禁用不是资产权限 |

T0是编排器，T1管交易，T2管交付和恢复，T3管点击体验；不要把四块重新揉成一个文件。B0–B5不反向依赖测试页面或本机cookie。Rust原生实现与Node参考模型并行对照，不能因参考模块通过就省略原生验收。

## 二、块之间怎样连接

| 交接 | 唯一可相信的输入 | 上层必须再核对 |
| --- | --- | --- |
| 购买→库存 | 实际项目、四类mint、owner、整数Token数量和收据 | 发行/转卖区别、规范账户、实际到账 |
| 库存→制造 | 真实Token/Source及不可变材料清单 | 来源、剩余量、是否已消费、费用上限 |
| 制造→合成 | 已验证LIVE Root、owner、revision、实际输入图 | 不重复引用、不跨锁、不凭名字替换资产 |
| 验证→成品 | 规则/验证器身份、设计ID、终态、品质、完整成品 | PASS不是原生确认；旧PASS不能用于改过的图 |
| 成品→产出 | 当前owner、完整Root、登记边界与Position | 一件资产只有一份当小时有效计权，旧债独立 |
| 市场→库存/产出 | 原listing、精确资产ID与价格、原子成交结果 | 托管和owner、合成锁、历史受益人、没有增发 |
| 浏览器→服务 | 固定字段、当前会话、run/revision/requestId | 重新执行所有权限与余额检查，不信任禁用按钮 |

金额和计数使用精确整数；规范字节、schema与摘要不可任意改名。HTTP和runtime的动作字段目前仍分别校验，修改时必须同时更新并运行跨层契约用例；本轮已修复一次WORK挂牌被另一层workId规则误拒的问题。**尚未声称拥有自动生成的统一ABI/HTTP/UI schema。**后续如统一schema，先冻结现有样例，再做保持语义的独立重构。

## 三、每次修改按这个顺序

1. 写清修改哪块、为何修改、会改变哪个接口；先列正常/重复/并发/失败和恢复预期。
2. 区分显示、交互、权限、科学模型、发行/收益和数据格式。显示改动不顺带改经济常量。
3. 跑该块验收，再跑直接上下游；余额/资产/权重变动必须逐笔对账，测试失败就回到该块修正。
4. 有原生账户、权限、ABI或状态迁移改动时，Node通过后仍须同配置原生Bank验收。钱包/RPC/真实环境另验。
5. 最后全量`npm test`、数学身份核对、浏览器走通、源码快照；保存新版本，不覆盖旧验收。

| 想改的东西 | 至少联动检查 |
| --- | --- |
| 页面名称、排列、步骤提示 | B8/T3，保留用户选择、草稿与原pending请求；页面测试和浏览器 |
| 购买/制造一步点选 | B1/B3→SDK→HTTP→页面；真实库存、不可变清单和失败回滚 |
| 三个市场外观或筛选 | T3；真实分类仍由T1/原生记录判定 |
| 挂牌期间继续产出 | 市场+B4+B5+B6+B7+B8；不是只把“登记”按钮改成可点 |
| 配方、容量、验证或品质 | B0/B2/B3/B4/B5/B6；新规则身份、旧资产兼容及重新验收 |
| 发行、费用或LAB排放 | B1/B3/B4/B6及经济复算；不能只改前端报价 |

有字段/含义变化时使用新schema或新发布身份，先说明旧数据如何读取、拒绝或迁移，禁止静默按新规则重算旧权益。目前已实现的兼容路径是旧本机checkpoint的明确市场迁移；**没有实现任意未来科学模型或经济版本的自动迁移系统**，需要升级时另立模块并验收。已有实例和历史债权的旧规则身份必须保留。

## 四、目前还不能拼上的块

正式原生三市场、挂牌继续产出与成交小时切分尚未实现。TAPE已确认可有效挂牌且继续ACTIVE；当前本机市场要求先退出，是清楚标注的先行模式。正式方案必须先解决旧收益归属、未来唯一计权、挂牌期间合成/转让互斥，以及取消不误伤首创资格，才可写对应代码。

完整范围见 [市场规格与原生缺项](MARKET-SPEC-AND-NATIVE-GAPS.md)、[最终剩余清单](FINAL-REMAINING-CHECKLIST.md)。未来生态世界通过生物实例和独立世界状态连接，不能提前混进原料或LAB结算模块。本轮没有上线。

2026-10-26补充：测试账号的T0当前只编排C310固定批量路径，逐件制造和用户自定图尚未接通；这也属于未完成积木，不能因已有主站核心就忽略API与用户流程。参考样本展示已拆为sample-construction.js，详见[构造模式和逐件缺项](CONSTRUCTION-MODES-AND-GAPS.md)。
