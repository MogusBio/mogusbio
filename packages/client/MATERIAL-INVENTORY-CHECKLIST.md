# A2.1 actual material inventory: checks fixed before implementation

Scope: a bounded, finalized, known-ID read for the existing fixed material planner. It creates no journal, signature, transaction, reservation, material, Source or Root. No material/economic/native ABI rule changes.

- [x] Accept only `{release,rpc,actor,projectIds,sourceIds}`; `rpc` must be the existing `ReadOnlyRpc`. IDs are unique 32-byte buffers/Uint8Arrays, copied before awaits and canonically sorted. No caller nonce, balance, Source prefix, account endpoint or arbitrary token account is accepted.
- [x] At most 8 requested projects and 16 Sources. Include every actual Source's project in the closure; the union must contain at most 8 projects, otherwise reject explicitly instead of truncating. Five common accounts + 8×(Project + four mints + four actor ATAs) + 16 Sources = at most 93 accounts in each final coherent batch, below RPC's 100-account limit.
- [x] Discover actual Sources with BaseConfig, initialized EconConfig, canonical Clock, ActorNonce and ordinary on-curve system Actor. Decode native ownership/header/PDA/domain/config/catalog before using Source project IDs.
- [x] Read the complete closure, then reread the same complete closure in one finalized RPC batch. Compare relevant previously observed owner/executable/data/lamport facts, ActorNonce and common records. Changed valid state returns `REPLAN_STALE_STATE` without usable inventory. Clock/nonce regressions or malformed records fail closed. Clock advancement alone is allowed.
- [x] Verify actual Projects and all four canonical Classic mints: fixed class order/catalog, caps/counters, canonical mint/authority, decimals0, no freeze authority, and supply ≤ issued − intakeBurned. Actual actor ATA amount must not exceed its mint supply.
- [x] Canonical missing or prefunded empty System ATAs are valid zero balances and are omitted from planner token Maps. Only successfully decoded Classic token accounts receive planner flags `initialized:true,native:false,frozen:false`; token owner/mint/account keys normalize to bytes. Malformed/frozen/wrong-owner/Token2022 accounts are rejected, never relabeled as absent.
- [x] Every Source must belong to Actor, match its canonical project/class/mint/catalog, and satisfy its exact identity, initial ticks and spent-prefix invariants. Initialization ≤ Project creation ≤ Source creation ≤ observed Clock; known Source unit totals for a project/class cannot exceed its actual intakeBurned counter. Requested missing Project/Source records fail closed.
- [x] Return `inventory:{projects,mints,tokens,sources}` Maps accepted directly by `planManufacturePartWorkflow` and the pure `prepareMaterialConsumption` preflight, plus a separate plain JSON summary using canonical decimal strings for all quantities. Show standard units, species ticks and milliRU separately; do not conflate these with LAB. Reads establish observed inventory only, not manufacturing success or spend authority.
- [x] Test unchanged genuine 76b checkpoint records and separately saved actual purchase Bank rows. Mark every mutated or reconstructed fixture as host-only. Test Source closure, actual remaining prefixes, missing ATAs, malformed accounts, changed nonce/balances/prefixes, exact account bounds, precision, normalization, duplicate IDs and unknown fields; transport must never send/sign/simulate or enumerate the wallet.

Verified locally: `node --test packages/client/test/material-inventory.test.mjs`, 9/9 passed. The real purchase-prefix read yields 30/60/15/15 standard units, 1,140,000 available species ticks and 14,400,000 milliRU, and feeds the existing exact manufacturing workflow and pure debit preflight without mutating the read snapshot. A host-only maximum closure reaches exactly `[21,93,93]` accounts across discovery/full/reread batches. No live RPC, wallet or chain mutation was used.

Success: `INVENTORY_READ` exposes `clock`, `nextNonce`, `contextSlot`, `actualInventoryVerified:true`, the four Maps under `inventory`, and `summary`. Summary has `standardUnits`, `sourceBudgets`, combined remaining-material `totals:{ticks,totalTick,creditInt}`, plus separate raw-standard-unit and existing-Source tick/milliRU breakdowns. All quantities in summary use decimal strings. A stale read exposes no `inventory` or `summary`.

Implementation-only follow-up: independent network/RPC honesty, target-network performance, manufacture execution and UI recovery are outside A2.1. The existing native transaction revalidates all spend identities and prefixes atomically later.
